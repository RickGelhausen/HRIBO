\section{About HRIBO}

HRIBO is a reproducible Snakemake workflow for bacterial ribosome-profiling
data. It takes gzip-compressed sequencing reads, a reference genome, and a
matching annotation and can produce:

\begin{itemize}
  \item adapter-trimmed reads, filtered alignments, and a combined quality report;
  \item strand-aware BAM, BigWig, and GFF files for genome-browser inspection;
  \item feature counts, normalized abundance, and direct translation-efficiency
        ratios for matched libraries;
  \item read-length summaries, metagene profiles, and data-driven TIS advice;
  \item REPARATION and optional DeepRibo ORF predictions;
  \item PCA, correlation, xTail and deltaTE results, with optional RiboRex; and
  \item a combined feature-level overview in spreadsheet, TSV, and GFF formats.
\end{itemize}

This manual is for people running HRIBO and interpreting its primary results.
The complete column-by-column result reference and more detailed biological
guidance remain available in the
\href{https://hribo.readthedocs.io/en/stable/}{online documentation}.

\important{HRIBO 2.0 writes selected results directly into the analysis
directory. The result ZIP and the \file{genome-browser/},
\file{ORF-predictions/}, and \file{quality-control/} layouts documented for
HRIBO 1.8 are no longer used. Start a 2.0 analysis with fresh configuration
and sample-sheet templates.}

\section{Requirements and installation}

\subsection{System requirements}

The supported platform is Linux on x86-64. Before starting, provide:

\begin{itemize}
  \item Conda or Micromamba;
  \item Apptainer installed on the host;
  \item enough disk space for the data, rule environments, containers, and
        selected prediction resources;
  \item a reference nucleotide FASTA and GFF3 or GTF annotation from the same
        assembly; and
  \item gzip-compressed FASTQ files.
\end{itemize}

The first run needs network access while Snakemake creates rule-specific Conda
environments and downloads containers, models, or reference data required by
the selected stages.

HRIBO's continuous integration tests Apptainer 1.5.3, but the workflow does
not enforce that exact version. A working modern installation such as 1.4.5
does not need to be replaced merely to match the test environment. Record the
version with the analysis and investigate it if container execution fails.

\subsection{Install the 2.0.0 release}

Keep the HRIBO checkout separate from every analysis directory:

\begin{lstlisting}[style=hribo]
git clone --branch 2.0.0 --single-branch \
  https://github.com/RickGelhausen/HRIBO.git /path/to/HRIBO

micromamba create --name hribo \
  --file /path/to/HRIBO/environment.linux-64.pin.txt
micromamba activate hribo

snakemake --version
apptainer version
\end{lstlisting}

Use \setting{conda create} instead of \setting{micromamba create} if Conda is
preferred. HRIBO runs from its checkout and is not installed with
\setting{pip}.

\file{environment.linux-64.pin.txt} is the reproducible \emph{launcher}
environment. It contains Snakemake, Conda, pandas, and the SLURM executor
plugin. It is not a monolithic environment containing every scientific tool.
Snakemake obtains those dependencies separately from \file{workflow/envs/} or
from the pinned containers when the corresponding rule is needed.

\section{Prepare an analysis}

\subsection{Create a project directory}

\begin{lstlisting}[style=hribo]
mkdir -p /path/to/my-analysis/{config,data,fastq}

cp /path/to/HRIBO/config/config.yaml \
  /path/to/my-analysis/config/config.yaml
cp /path/to/HRIBO/config/samples.tsv \
  /path/to/my-analysis/config/samples.tsv
\end{lstlisting}

Copy or link the genome, annotation, and reads into the new project. A small
project initially looks like:

\begin{lstlisting}[style=hribo]
my-analysis/
|-- config/
|   |-- config.yaml
|   +-- samples.tsv
|-- data/
|   |-- genome.fa
|   +-- annotation.gff3
+-- fastq/
    +-- ribo-control-1.fastq.gz
\end{lstlisting}

Relative paths in the configuration and sample sheet are resolved from this
analysis directory. The FASTA sequence identifier---the first word after
\setting{>} in each header---must exactly match annotation column 1, including
capitalization and any version suffix.

\subsection{Describe the libraries}

The sample sheet is tab-separated and has exactly these five headers:

\begin{lstlisting}[style=hribo]
method	condition	replicate	fastqFile	fastqFile2
RIBO	Control	1	fastq/ribo-control-1.fastq.gz	""
RIBO	Control	2	fastq/ribo-control-2.fastq.gz	""
RNA	Control	1	fastq/rna-control-1.fastq.gz	""
RNA	Control	2	fastq/rna-control-2.fastq.gz	""
\end{lstlisting}

Leave \setting{fastqFile2} empty for single-end data. For paired-end data,
place read 1 in \setting{fastqFile} and read 2 in \setting{fastqFile2}.
Single- and paired-end libraries may occur in the same sheet.

\begin{tabularx}{\textwidth}{@{}p{0.19\textwidth}Y@{}}
\toprule
\textbf{Column} & \textbf{Required value} \\
\midrule
\setting{method} &
One of \setting{RIBO}, \setting{TIS}, \setting{TTS}, \setting{RNA},
\setting{RNATIS}, or \setting{RNATTS}; capitalization matters. \\
\setting{condition} &
An alphanumeric biological condition such as \setting{Control} or
\setting{Treated}. Spaces, underscores, and hyphens are not accepted. \\
\setting{replicate} &
A positive integer. Each method/condition/replicate combination must be
unique. \\
\setting{fastqFile} &
The gzip-compressed single-end FASTQ or read-1 FASTQ. \\
\setting{fastqFile2} &
The gzip-compressed read-2 FASTQ, or a genuinely empty cell for single-end
data. \\
\bottomrule
\end{tabularx}

HRIBO names each library
\file{<method>-<condition>-<replicate>}, for example
\file{RIBO-Control-1}. This name is used throughout the result tree.

\subsection{Configure the inputs}

Edit the complete copied \file{config/config.yaml}. Do not replace it with the
short excerpt below, because HRIBO validates the complete section structure.
At minimum, check all adapter fields, input paths, alternative starts, and
requested stages:

\begin{lstlisting}[style=yaml]
biologySettings:
  adapterS3: ""
  adapterS5: ""
  adapterP3R1: ""
  adapterP5R1: ""
  adapterP3R2: ""
  adapterP5R2: ""
  genome: "data/genome.fa"
  annotation: "data/annotation.gff3"
  samples: "config/samples.tsv"
  alternativeStartCodons: ["GTG", "TTG"]

workflowSettings:
  stages:
    - mapping
    - qc
    - tracks
\end{lstlisting}

The single-end adapter fields are \setting{adapterS3} and
\setting{adapterS5}; the four \setting{adapterP*} fields describe paired-end
read 1 and read 2. An empty value means no adapter is supplied. It must not be
used as a placeholder for an unknown library preparation.

\subsection{Choose the results}

A stage specifies a deliverable, not an isolated step. Snakemake automatically
runs its prerequisites. For example, requesting \setting{predictions} also
performs the trimming, mapping, filtering, and counting needed to make those
predictions.

\begin{longtable}{@{}>{\raggedright\arraybackslash}p{0.24\textwidth}
                       >{\raggedright\arraybackslash}p{0.68\textwidth}@{}}
\toprule
\textbf{Stage} & \textbf{Purpose} \\
\midrule
\endhead
\setting{trimming} & Trim or assemble reads and run raw/processed FastQC. \\
\setting{mapping} & Create final unique BAMs after rRNA/tRNA removal. \\
\setting{qc} & Build the combined MultiQC report. \\
\setting{tracks} & Create raw and normalized strand-aware BigWigs. \\
\setting{genome_tracks} & Create possible start, stop, alternative-start, and RBS tracks. \\
\setting{readcounts} & Count reads and create annotation/abundance workbooks. \\
\setting{metagene} & Summarize read lengths and start/stop-centred profiles. \\
\setting{tis_advisor} & Assess mapped read ends, usable lengths, and P-site offsets. \\
\setting{correlation} & Compare binned genomic coverage between libraries. \\
\setting{pca} & Inspect sample grouping using normalized counts. \\
\setting{predictions} & Run REPARATION and, when enabled, DeepRibo. \\
\file{differential_expression} & Run xTail and deltaTE, optionally run RiboRex, and build a cross-condition report for valid contrasts. \\
\setting{overview} & Combine annotation, abundance, predictions, and enabled differential results. \\
\bottomrule
\end{longtable}

\setting{stages: "preprocessing"} selects trimming, mapping, and QC.
\setting{stages: "full"} selects every stage, including differential
expression. A custom YAML list is usually the clearest choice. A one-off
command-line override is also possible:

\begin{lstlisting}[style=hribo]
--config stages=mapping,qc,tracks
\end{lstlisting}

\important{\setting{full} requires at least two conditions with matched RIBO
and RNA libraries, at least two biological replicates on both sides of every
contrast, and equal selected RIBO/RNA replicate counts. The
\setting{overview} stage also builds the prediction results it combines and is
not a lightweight summary-only action.}

When no RIBO library is present, HRIBO removes predictions, differential
expression, and overview. Without a RIBO, TIS, or TTS library, it also removes
metagene and TIS-advisor work. The resolved stage list is printed at startup.

\subsection{Review analysis-specific settings}

\paragraph{Prediction.}
\setting{predictionSettings.deepribo} accepts \setting{on} or \setting{off}.
REPARATION is the base predictor. With DeepRibo enabled, the genome may contain
only uppercase A, C, G, T, and N. \setting{deepriboASiteOffset} is measured
from a read's 3-prime end to the ribosomal A-site. The template value 12 came
from an \emph{E. coli} setup and must be reviewed for the protocol. The TIS
advisor evaluates P-site offsets from both read ends and, for RIBO libraries,
may also suggest a separate DeepRibo A-site value. This is advice only: compare
RIBO libraries before changing the single global setting and rerunning
predictions. HRIBO never applies it automatically.

\paragraph{Differential analysis.}
\setting{differentialExpressionSettings.features} contains case-sensitive
feature types from annotation column 3. If some requested types are absent,
HRIBO warns and counts those that exist; if none are present, it stops with an
error. \setting{differentialExpressionSettings.}\allowbreak\setting{riborex}
is \setting{off} by
default. Set it to \setting{on} to create the optional RiboRex workbooks and
include its TE estimate as supplementary evidence; it does not change the RNA,
RIBO, or TE states called from deltaTE. A contrast such as
\setting{Treated-Control} is left minus right, so a positive log2 fold change
means higher signal in \setting{Treated}. The filtered workbook sheets use the
configured \setting{padjCutoff} and inclusive \setting{log2fcCutoff}
boundaries. The cross-condition report uses separate
\setting{detectionMinCPM}, \setting{detectionMinCount}, and
\setting{detectionMinReplicates} thresholds (defaults: 1 CPM, 10 reads, 2
replicates). A replicate passes detection only when both CPM and raw count
meet their thresholds. A feature is detected if enough replicates pass, not
detected if none pass and enough usable replicates were available, and uncertain
otherwise. A zero-depth sample has undefined CPM and is not a usable
replicate. Detection is separate for RNA and RIBO; these settings do not
change the statistical tests.

\paragraph{Metagene and TIS settings.}
Review the allowed read lengths and mapping ends for the library protocol.
Metagene filtering and plotting are controlled independently from the TIS
advisor. A wide TIS-advisor length range can retain evidence outside the
expected metagene range.

\section{Run HRIBO}

\subsection{Validate before computing}

Activate the launcher environment, enter the analysis directory, and first
construct the complete job graph without running it:

\begin{lstlisting}[style=hribo]
micromamba activate hribo
cd /path/to/my-analysis

/path/to/HRIBO/run_hribo.sh \
  --configfile "$PWD/config/config.yaml" \
  --cores 8 \
  --dry-run all
\end{lstlisting}

The preflight checks configuration keys, sample design, input files, FASTQ
structure, reference coordinates, and sequence identifiers. Fix every
reported error before starting a long analysis. Listing many planned jobs is
normal in a dry-run.

\subsection{Run locally}

\begin{lstlisting}[style=hribo]
/path/to/HRIBO/run_hribo.sh \
  --configfile "$PWD/config/config.yaml" \
  --cores 8 \
  --rerun-incomplete \
  --show-failed-logs all
\end{lstlisting}

The wrapper selects HRIBO's Snakefile, enables Conda and Apptainer, prints
commands, keeps independent jobs running after a failure, waits for filesystem
latency, and limits concurrent memory-intensive REPARATION jobs. Additional
arguments are passed to Snakemake. Always keep the explicit \setting{all}
target at the end.

\subsection{Use a larger temporary location}

On a workstation or virtual machine, \file{/tmp} may be much smaller than the
analysis filesystem. Before launching HRIBO, point ordinary temporary files
and Apptainer's cache/build area to directories with enough space:

\begin{lstlisting}[style=hribo]
mkdir -p "$PWD/.tmp/general" \
         "$PWD/.tmp/apptainer-cache" \
         "$PWD/.tmp/apptainer-build"

export TMPDIR="$PWD/.tmp/general"
export APPTAINER_CACHEDIR="$PWD/.tmp/apptainer-cache"
export APPTAINER_TMPDIR="$PWD/.tmp/apptainer-build"
\end{lstlisting}

Set these variables in the same shell that launches HRIBO. Confirm that the
chosen filesystem has enough capacity and is suitable for temporary data.
The \setting{tmpdir=/tmp} text in Snakemake's displayed resources is a
temporary-resource assignment; it does not mean every rule writes its large
outputs there.

\subsection{Resume an interrupted analysis}

The normal run command with \setting{--rerun-incomplete} keeps completed
outputs and schedules only missing or incomplete work. If Snakemake reports a
stale lock, first confirm that no HRIBO process is using the analysis
directory, then unlock that exact project once:

\begin{lstlisting}[style=hribo]
/path/to/HRIBO/run_hribo.sh \
  --configfile "$PWD/config/config.yaml" \
  --unlock
\end{lstlisting}

Never unlock an analysis while another process is active. After unlocking,
run the usual command again with \setting{--rerun-incomplete all}.

\subsection{Optional SLURM execution}

For a SLURM cluster, set the site account and partition in
\file{workflow/profiles/slurm/config.yaml}, activate the launcher environment,
and call \file{slurm_run.sh} from the analysis directory:

\begin{lstlisting}[style=hribo]
/path/to/HRIBO/slurm_run.sh \
  --configfile "$PWD/config/config.yaml" \
  --dry-run all

/path/to/HRIBO/slurm_run.sh \
  --configfile "$PWD/config/config.yaml" \
  --rerun-incomplete \
  --show-failed-logs all
\end{lstlisting}

Modules, accounts, partitions, and storage policies are site-specific. They
are not guessed by HRIBO.

\section{Understand the results}

HRIBO writes into the analysis directory. Only the selected stages and their
prerequisites are present. For a typical analysis, inspect results in this
order:

\begin{enumerate}
  \item Open \file{qc/multi/multiqc_report.html} and review every library.
  \item Check correlation and PCA when multiple libraries are present.
  \item Review fragment lengths, metagene profiles, and TIS-advisor evidence.
  \item Inspect BAM, BigWig, and GFF files at representative loci.
  \item Begin feature-level review with \file{auxiliary/overview.xlsx}, then
        return to the method-specific workbook for important candidates.
\end{enumerate}

\normalsize

\subsection{Quality control and final alignments}

MultiQC combines diagnostics from raw reads, trimming, mapping, and rRNA/tRNA
filtering. Compare read counts, quality, fragment lengths, mapping rates, and
depletion across all libraries. A completed report means that the report was
generated; it does not mean that the experiment passed biological quality
control.

\file{maplink/<library>.bam} is a relative symbolic link to the final unique
BAM below \file{bam/}. Moving the complete analysis tree preserves the link.
When exporting BAMs alone, dereference the links and copy each corresponding
\file{.bam.bai} index.

\subsection{Coverage and genome-browser tracks}

Each library receives four transcript-oriented views:

\begin{description}[style=nextline,leftmargin=1.6em]
  \item[\setting{global}] Coverage over all aligned reference blocks.
  \item[\setting{centered}] Coverage after clipping the aligned read ends.
  \item[\setting{fiveprime} and \setting{threeprime}]
        One-position views anchored at the mapped transcript-oriented end.
\end{description}

All four default views are built from the final unique, rRNA/tRNA-filtered
alignments. Each is available as \setting{raw}, \setting{mil} (counts per
million mapped reads), and \setting{min} (scaled to the smallest mapped
library). Forward values are positive and reverse values are negative so a
browser can draw the strands on opposite sides of zero; the negative sign is
a display convention, not negative abundance.

Use the BAM and raw tracks to judge evidence within one library. Use an
appropriate normalized track for cross-library comparison, and load the motif
GFFs or \file{tracks/updated_annotation.gff} alongside them.

\subsection{Counts, abundance, and direct TE}

\file{annotation_unique.xlsx} uses uniquely mapped reads;
\file{annotation_total.xlsx} includes fractional contributions from
multi-mapped reads. Both provide feature-level annotation and one RPKM column
per library. The smaller \file{unique_read_counts.xlsx} and
\file{total_read_counts.xlsx} summarize counts by feature class.

When a Ribo-like library has a matching RNA control with the same condition
and replicate, HRIBO reports a direct translation-efficiency value:

\[
  \mathrm{TE}_{\mathrm{direct}} =
  \frac{\mathrm{Ribo\mbox{-}like\ RPKM}}{\mathrm{matched\ RNA\mbox{-}like\ RPKM}}.
\]

This is a ratio, not a differential log2 fold change. RPKM values use the
mapped total across the complete library, including all contigs.

\subsection{Metagene profiles and TIS advice}

Start with \file{metageneprofiling/read_length_fractions.html}, then open each
library directory for the configured start- and stop-centred profiles. Check
which read lengths contribute, the selected read end, the normalization, the
number of included CDSs, and whether the signal fits the experimental
protocol.

The TIS-advisor HTML report is the human-readable entry point. Its
machine-readable companions are:

\begin{itemize}
  \item \file{tis_recommendation.json}, containing the complete result; and
  \item \file{read_length_evidence.tsv}, containing evidence for every
        evaluated length.
\end{itemize}

Read the recommendation, confidence, warnings, and plots together. A result
with no recommended offset can be scientifically valid when the data do not
contain a trustworthy initiation peak.

The DeepRibo section converts usable 3-prime-to-P-site estimates to candidate
3-prime-to-A-site offsets by subtracting one codon. It suggests one scalar only
when the read lengths agree and represent enough of the RIBO library. Compare
that suggestion with \setting{predictionSettings.deepriboASiteOffset} and with
other RIBO libraries. Change the global setting and rerun predictions only
after review; the advisor does not change it for you.

\subsection{ORF predictions}

REPARATION calls are stored in
\file{auxiliary/predictions_reparation.xlsx}. DeepRibo adds
\file{auxiliary/predictions_deepribo.xlsx} only when enabled. Review
coordinates, prediction score or probability, contributing libraries,
sequence, RPKM/TE, and annotation context. Predictor support is evidence to
evaluate, not proof of translation.

\file{tracks/updated_annotation.gff} combines the supplied annotation with
accepted prediction calls for browser inspection. Keep the individual
workbooks when reporting which predictor supported an ORF.

\subsection{Differential results}

Open \file{diffex_summary/condition_overview.html} to scan a searchable,
sortable feature-by-condition matrix of RNA and RIBO detection and a separate
feature-by-contrast matrix of RNA, RIBO, and translation-efficiency (TE)
changes. Every view starts with separate \setting{Locus tag} and
\setting{Identifier} columns. The locus tag comes from the annotation's
\setting{locus_tag} attribute, falls back to \setting{gene_id}, and is blank
when neither is available. The identifier is the exact differential-table key,
normally \file{<sequence>:<start>-<end>:<strand>}. Click either identifying
heading or a condition or contrast heading to sort; click it again to reverse
the direction. Both identifying columns remain frozen on wider screens; on
narrow screens only the locus tag remains frozen so result columns can be
scrolled into view. The adjacent
\file{condition_overview.xlsx} contains the same five views in
\file{RNA_detection}, \file{RIBO_detection}, \file{RNA_change},
\file{RIBO_change}, and \file{TE_change} sheets, with frozen panes, native
Excel filters, and the same two-identifiers-plus-matrix layout. Both identifying
columns and all matrix columns can be sorted. Its directional cells remain
numeric so Excel sorts their signed log2 fold changes correctly.
The adjacent \file{condition_matrix.tsv},
\file{contrast_matrix.tsv}, and \file{browser_tracks.tsv} retain the tabular
results. The two feature-level TSVs retain \setting{feature_id} and add
\setting{locus_tag} as a separate field. Selected detected features and
up/down contrasts are exported as separate
\file{diffex_summary/browser/*.gff3} tracks. Load these alongside
the final BAM or BigWig tracks for locus inspection. The report is part of
\file{differential_expression}; it does not require the prediction-dependent
\setting{overview} stage.

Detection states are detected, not detected, or uncertain, based on the
configured count, CPM, and replicate thresholds. Not detected means below
the chosen evidence threshold at this sequencing depth, not proven biological
absence. Contrast states are up, down, no directional call, or not tested.
The machine value \setting{not\_significant} means that both directional
thresholds were not met; it does not establish a high adjusted p-value or
zero effect, and is not interchangeable with not detected. The RNA, RIBO, and
TE contrast states come from deltaTE; xTail and, when enabled, RiboRex TE
estimates are supplemental evidence rather than votes in a combined test. See the
\href{https://hribo.readthedocs.io/en/stable/differential-summary.html}{online
cross-condition report guide} for interpretation and browser-track use.

For \file{<left>-<right>}, positive log2 fold changes mean higher signal in the
left condition. Each xTail and deltaTE workbook has an \setting{all} sheet and
prefiltered up/down sheets; the same applies to the RiboRex workbook when that
optional analysis is enabled. deltaTE separates RNA, RIBO, and TE effects.

Always inspect effect size and adjusted p-value together, using the cutoffs
recorded in the configuration. The enabled tools do not produce interchangeable
statistics; use xTail and optional RiboRex as supplementary evidence rather
than extra votes in the deltaTE calls.

\subsection{Combined overview}

\file{auxiliary/overview.xlsx} is the most convenient feature-level starting
point. Its \setting{all} sheet joins annotated and predicted CDS-like
coordinates with sequence, per-library abundance/direct TE, prediction
evidence, and enabled differential statistics. Other sheets contain annotated
or feature-type subsets.

\file{auxiliary/overview.tsv} provides the same main table for scripts.
\file{auxiliary/overview.gff} represents the combined CDS set, while
\file{auxiliary/overview_misc.gff} contains non-CDS features. Use the
\href{https://hribo.readthedocs.io/en/stable/table-reference.html}{online
result-table reference} for current sheet names, dynamic column conventions,
coordinates, and missing-value rules.

\section{Troubleshooting}

\subsection{Find the first real failure}

Start with the first failing Snakemake rule, not the final downstream summary.
The terminal names its rule and normally points to a file below \file{logs/}.
The recommended run command includes \setting{--show-failed-logs}; preserve
the complete first traceback when requesting help.

\subsection{Preflight stops before any rule}

This is intentional. Common causes are a misspelled configuration key or stage,
incorrect sample-sheet headers, a path resolved from the wrong directory,
malformed or uncompressed FASTQ, mismatched FASTA/GFF sequence identifiers,
or a differential contrast that the sample design cannot support. Correct the
source input and repeat the dry-run rather than editing generated files.

\subsection{A requested annotation feature is absent}

Feature types are exact, case-sensitive values from GFF/GTF column 3. If the
configuration requests \setting{["CDS", "sRNA"]} but the annotation contains
only CDS, HRIBO warns, skips sRNA, and continues with CDS. It stops only when
none of the requested feature types occur. Choose feature names that genuinely
exist in the supplied annotation.

\subsection{Zero or empty biological results}

Zero mapped reads are fatal because CPM, RPKM, and normalized coverage cannot
be calculated honestly. Work backwards through trimming, reference choice,
mapping, and rRNA/tRNA depletion.

By contrast, an all-zero metagene profile, a header-only subset, or a
\setting{confidence: none} TIS recommendation can be a valid completed result.
Check the rule status, mapped depth, configured lengths and filters, annotation
boundaries, and whether the protocol should produce the expected signal.

\subsection{REPARATION corrects a P-site estimate}

For a sparse or noisy read length, Plastid can estimate a P-site offset that
falls outside the read. HRIBO replaces only that impossible estimate with the
\setting{default} value in Plastid's table before REPARATION calculates
occupancy and ORF predictions. The log names the read length, original value,
and replacement, and \file{p_site_offsets.txt} retains a comment recording the
correction. The run may continue successfully because the fallback is valid;
inspect \file{p_site_offset.png} when present and the offset table. Corrections
for many well-represented lengths warrant closer review of the signal,
annotation, configured footprint range, and library quality.

\subsection{Conda or Apptainer fails}

Confirm the active launcher environment and record:

\begin{lstlisting}[style=hribo]
micromamba activate hribo
snakemake --version
apptainer version
\end{lstlisting}

The bundled wrappers enable both Conda and Apptainer. The first execution may
need network access and considerable cache space. If storage is limited,
configure \setting{TMPDIR}, \setting{APPTAINER_CACHEDIR}, and
\setting{APPTAINER_TMPDIR} before launching. Replacing a pinned scientific
container with unrelated locally installed tools changes the analysis
environment and should not be used as an unexplained workaround.

\section{Reproducibility, citation, and help}

For every analysis, retain:

\begin{itemize}
  \item the HRIBO version or commit;
  \item the exact \file{config.yaml} and \file{samples.tsv};
  \item Snakemake and Apptainer versions;
  \item the launch command and resolved stage list;
  \item primary results and relevant logs; and
  \item any manual changes to offsets, filters, cutoffs, or generated tables.
\end{itemize}

If HRIBO contributes to published work, cite:

\begin{quote}
Gelhausen R, Svensson SL, Froschauer K, et al. HRIBO:
high-throughput analysis of bacterial ribosome profiling data.
\emph{Bioinformatics}. 2021;37(14):2061--2063.
\href{https://doi.org/10.1093/bioinformatics/btaa959}
{doi:10.1093/bioinformatics/btaa959}.
\end{quote}

For current instructions, visit
\href{https://hribo.readthedocs.io/}{hribo.readthedocs.io}. To report a
reproducible problem, use
\href{https://github.com/RickGelhausen/HRIBO/issues}{the GitHub issue tracker}
and include the first failing rule, its complete log, the software versions,
the effective configuration, and a redacted sample sheet. Do not upload
confidential sequencing data.

\section{Pre-run checklist}

\small
\begin{itemize}[itemsep=0pt,parsep=0pt,topsep=0.2em]
  \item The HRIBO checkout and analysis directory are separate.
  \item The release and launcher environment report the expected versions.
  \item The FASTA and annotation describe the same assembly and sequence IDs.
  \item Every FASTQ is gzip-compressed and referenced from exactly one valid
        sample-sheet row.
  \item Adapter settings match the single- or paired-end library preparation.
  \item The requested stages match the available library types and study
        design.
  \item Differential feature types occur in annotation column 3 and contrast
        direction is recorded.
  \item DeepRibo's offset and reference alphabet have been reviewed when it is
        enabled.
  \item Temporary and cache locations have enough free space.
  \item The complete \setting{--dry-run all} succeeds before the production
        command is launched.
\end{itemize}
